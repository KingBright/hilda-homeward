# 框架边界与迭代方法

## 源码只有一份

`src` 是唯一作者源。`tools/build.mjs` 按确定顺序打包脚本和样式，产生两个相同的兼容发布 HTML、`dev.html` 和带模块 SHA-256 的 `build-manifest.json`。没有手工维护第三份游戏。根目录旧文件名继续可用。

当前保留轻量依赖注册器而不引入完整引擎或打包依赖，目的是维持离线双击玩法。模块通过 `Homeward.define(id, dependencies, factory)` 声明依赖，通过工厂参数接收依赖；运行时仅暴露 `Homeward` 一个注册入口。实际游戏启动在 `bootstrap.js`。不要依赖文件的加载先后去偷读另一个文件的全局变量。

## 修改什么，到哪里改

| 工作 | 位置 | 验证 |
| --- | --- | --- |
| 一幕的建筑、道具摆放、角色站位 | 对应 `scenes/*/art.js` | 截图、画面遮挡、冷热光源位置 |
| 同一幕的对白、行动、门槛与提示 | 对应 `scenes/*/logic.js` | 顺序、错误操作、回访、可达性 |
| 物品外形和放大细节 | `art/props.js`、`art/items.js` | 缩略图与放大图的轮廓一致 |
| 道具材质、用途与组合 | `content/items.js` | 配方、无损拒绝、不触发无关动作 |
| 可选环境故事 | `content/details.js` | 必须在画面里画出对应物件；不能阻塞主线 |
| 机关共同几何 | `content/mechanisms.js` | 显示与热点位置一致；轮距、齿数约束 |
| 环境材质和前景 | `art/finishing.js` | 不遮住核心物件；减少动态模式 |
| 进度兼容 | `engine/state.js`、`engine/storage.js` | V2 迁移、主备损坏、存储拒绝 |
| 输入、演出和系统连接 | `engine/runtime.js` | 点击、拖动、键盘、暂停、移动后执行 |

## 场景的最小接口

一个场景导出对象：`name / english / actLabel / mood / start / ground / intro / hotspots / act / objective / hints`；可选 `drag` 和 `chapter`。

`hotspots(state)` 返回含 `id,label,x,y,w,h` 的列表，物件的世界坐标不能随视口像素尺寸变化。`walkX` 表示合乎地形的操作站位。`kind` 可用于拾取、出口或观察反馈。

`act(game,id,item)` 是行动入口。通过 `game.set/take/consume/note/say/work/go` 改变世界，不要直接查找界面元素，也不要改浏览器存储。长动作通过 `game.work(duration,label,after)` 延迟生效；跨幕前后的动作必须能取消。

场景的图案不能独立“猜测”机关答案。水路由 `engine/hydraulics` 同时向逻辑和美术提供连通结果；齿轮轴距、齿数、热点通过共同几何模块读取。这比复制一张答案数组到两处可靠。

## 存档是公开协议

新增标记必须加入允许列表与验证。新增数值要有有限范围。修改版本时写迁移，迁移不得消耗玩家已有道具、清掉已完成章节或写回旧版本存储位置。禁止用宽松的 `Object.assign` 直接信任导入 JSON。

`SaveStore` 先独立验证每份候选，再保留最后一份已知有效快照。存档失败时游戏继续运行并说明导出方式，不能用异常把整个游戏循环中断。

## 仍然有意保留的集中点

`engine/runtime.js` 仍负责输入、对白、菜单与帧循环的编排。此次没有把每一个函数都变成类或插件。之后有第二套对白 UI 或第二种交互模式时，再沿稳定接口拆出控制器，而不是先造一个很大但只有一个使用者的通用框架。

同样，十二幕仍采用固定画布和脚部高度函数，不是任意场景导航网格。新增复杂的前后景绕行、楼梯或攀爬前，应先引入可达性图，并让逻辑和动画共用行走约束。
