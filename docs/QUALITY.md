# 品质计划：从完整原型到可发行作品

## 本轮完成的范围

本轮是 V3 工坊版：把已有十二幕变成可分别编辑的美术与逻辑，补上画面中的观察、物品信息、连通图水路、试压、齿轮对位、物品规则与旧进度迁移。原有多幕主线和安全归家结局继续保留。

测试分成两种证据：纯逻辑单元测试；真实浏览器事件驱动的完整通关及回归。Fixture 载入只用于专项回归，不宣称这些跳场景测试是第二遍完整通关。报告保留被测文件的 hash 和测试环境。

## 这一版还不是商业成品

视觉仍主要依赖程序化 SVG，角色缺少连续的拿取、攀爬、拖拽重物、对视和救援专用动画。水泵与齿轮更具过程，但多幕仍是单个主机关串联，尚不是具有多条局部调查线的长篇商业冒险。

真实手机、Safari、Firefox、低端设备、不同辅助输入和完整离线安装尚未形成验收矩阵。没有配音、发行级本地化、完整无障碍通关声明、商业 IP 授权证明，也没有用玩家盲测证明剧情节奏。

## 下一轮优先做一段可衡量的精修样板

以“雨中北门 → 森林 → 水泵”为样板段，不先无限增加房间。

1. 统一美术制作规范：人物轮廓、线宽、材质、道具比例、近中远层、灯光方向与颜色脚本；为高频物件制作明确的空闲、可用、使用中和完成状态。
2. 制作角色表演：脚掌接地、取物前站位、物体受力、双人协作动作、对话目光；角色不应靠一行工作文字代替全部表演。
3. 拓展局部谜题：允许在两三个可回访场景中调查、提出解释、尝试并验证；错误应给玩家新信息，而非统一“不能使用”。
4. 邀请未看过攻略的人试玩，记录第一次理解目标的时间、误点、误用、提示次数、存档恢复和中途离开的原因。改进以观察为准，而不是以功能数量为准。

## 发行候选的硬门槛

每个谜题需通过初次、错误顺序、重复操作、回访、存档恢复、取消和所有受支持输入方式。场景改图后必须重新检查热点与遮挡。进度迁移必须保留旧存档样本。玩法流程中不得有未捕获异常、必需物品永久丢失或无法退出的状态。

建立真实设备基线后再确定帧时间与内存预算；当前没有测量依据，不虚设“全设备 60fps”。美术验收、叙事验收、性能验收和权利审查应分别通过，不能用单元测试数量代替其中任何一个。
