# 品质计划：从完整原型到可发行作品

## 本轮完成的范围

本轮是 V3.1 雨夜精修。在 V3 模块化基础上精修北门、森林、水泵：主角接触动作、逐步机关演出、同伴制动、进水隔离、维护流程和连续检修台。十二幕与安全归家结局保留。

测试分成两种证据：纯逻辑单元测试；真实浏览器事件驱动的完整通关及回归。Fixture 载入只用于专项回归，不宣称这些跳场景测试是第二遍完整通关。报告保留被测文件的 hash 和测试环境。

## 这一版还不是商业成品

视觉仍主要依赖程序化 SVG，前三个精修地点已有拿取、拉绳、转轮和持杆动作，但后续章节仍缺少成套的攀爬、搬运、对视与救援表演。水泵与齿轮更具过程，但多幕仍是单个主机关串联，尚不是具有多条局部调查线的长篇商业冒险。

真实手机、Safari、Firefox、低端设备、不同辅助输入和完整离线安装尚未形成验收矩阵。没有配音、发行级本地化、完整无障碍通关声明、商业 IP 授权证明，也没有用玩家盲测证明剧情节奏。

## 下一轮优先验证什么

精修样板已经落地，下一轮不应立即扩成大量新房间。先让未看过攻略的人试玩这段路径，记录目标理解、误点、提示次数和离开原因，再把实测有效的交互规范扩展到档案室、升降站和风暴救援。

还需要近中远景的统一比例、更多姿态和眼神、同伴的多角色动作编排、可回访地点之间的局部推理线，以及真实触屏和低端设备的性能基线。自动化通关不代表普通玩家能自然读懂线索。

## 测试边界

`tests/playthrough.py` 连续走完十二幕，随后执行专门回归。浏览器加载完整发布 HTML；隔离环境使用明确的内存存储适配器，不将它表述为浏览器原生持久化结果。

`tests/chapter-regressions.py` 覆盖拖动取消、移动后操作、菜单暂停、取物中途重载、重复输入、旧进度保留、干管试压拒绝、带压锁定、触屏与键盘、减少动态及热点遮挡。`tests/native-storage.py` 另在允许 HTTP 和 file 导航的 CI 环境中检查原生存储。容器受策略限制无法导航时应明确记录，不绕过限制或把适配器结果冒充真机结果。

## 发行候选的硬门槛

每个谜题需通过初次、错误顺序、重复操作、回访、存档恢复、取消和所有受支持输入方式。场景改图后必须重新检查热点与遮挡。进度迁移必须保留旧存档样本。玩法流程中不得有未捕获异常、必需物品永久丢失或无法退出的状态。

建立真实设备基线后再确定帧时间与内存预算；当前没有测量依据，不虚设“全设备 60fps”。美术验收、叙事验收、性能验收和权利审查应分别通过，不能用单元测试数量代替其中任何一个。
