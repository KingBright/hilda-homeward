# V3.5 伸手可及

## 场景比例

主角缩放从全场景固定值改为 `content/staging` 中的舞台设定。家中由 1.36 调整为 1.92，妈妈使用 2.38；对白头像仍使用独立的头像坐标空间，不随场景放大。开场站位与枝枝跟随距离也随比例调整，避免放大后人物挤在一起。

家中窗台整体下移 90 个世界单位，纸鸟落在窗边可以触及的位置；挂灯与提环降低到主角能实际握住的高度。画面、热点和接触目标一起调整，而不是只放大人物或只挪点击框。归家场景共用这些画面修正。

其余多数场景使用 1.52 至 1.60 的主角比例；复杂屋顶协作保留原来的舞台比例。钟楼入口加入与角色行走高度共用几何的检修坡道，使三根齿轮轴可以依次走近操作。水钟的旁路轮和排洪飞轮下移，并通过连杆与原有机械连接；钟舌增加可见检修梯和踏台，登台包垫后回到地面。

## 拿取与手部表现

新 `engine/body-motion` 提供可以按时间重复采样的身体姿势。上臂与前臂固定为 25、27 个局部单位，通过关节角插值形成伸手弧线，不再随动作进度伸长骨骼。脚、膝、身体倾斜与接触目标共同采样；手掌按前臂方向转动，握持和放松使用不同掌形与手指线条。远侧手臂绘制在衣服后面，避免覆盖胸前服饰。

来信、提灯、围巾、曲柄、森林绳圈、铁钩、升降站救援绳、三枚齿轮和羊毛毡采用可见的接触或拿取过程。手触及后，物品从原位置移到手中，再收好；来源只在演出层暂时隐藏，物品与完成标志在动作结束时提交。暂停冻结演出；中断重载保留未完成的物件，不提前消耗或发放。

升降站配重、制动，齿轮入轴，石灯遮光，接过音叉，水钟旁路与归家倒茶也增加了动作过程。倒茶显示手持茶壶与茶流。水钟最终操作中的音叉消耗改到完成时，避免操作未结束却已丢失物品。

这里仍是风格化二维骨架和程序化手掌，不是完整的手指骨骼、物理抓握或真人动作捕捉。不是每一个纯观察、提示与对话热点都播放取物动作；这些不改变实体物件。复杂多角色交接与动作审美仍需要持续实机试玩。

## 模块

`content/staging.js` 管理场景尺度和跟随间距；`engine/body-motion.js` 负责固定骨长的纯姿势计算；`art/performer.js` 将姿势绘制成肢体、掌形和手持物；`content/choreography.js` 提供接触点和站位。存档结构与 V3 键保持不变。

## NAS 发布

运行 `bash deploy.sh` 委托给 `tools/deploy-nas.sh`。发布前要求完整通关、动作、对白、音频和原生存储报告通过并对应当前 HTML。脚本使用已有 SSH 主机信任，不关闭主机密钥检查；先备份两个部署目录中的现有文件，再上传校验，原子替换每一个 HTML 文件。不会递归修改其他游戏目录权限。

两个目标目录是 `/var/www/games/hilda` 与 `/volume1/web/games/hilda`；每处同时更新 `index.html` 和旧入口 `hilda-homeward-v2.html`。备份位于各目录的 `.backups/<版本-UTC时间-构建前缀>/`。多文件替换不是跨文件系统事务，如遇 NAS I/O 故障应使用该备份恢复，并重新核对每个文件的校验值。

公开页面响应必须与被测 HTML 的 SHA-256 相同，部署成功记录保存在 `previews/v3.5/nas-deployment.json`。源码本地提交、NAS发布和 GitHub 推送是三个独立动作；本轮发布不要求修改其他项目、创建分支或清理浏览器进度。
