# V3.7 让世界说话

## 修复眼睛离开脸部

根因是人形眼睛仍继承 CSS 的 `transform-box: fill-box` 和居中 `transform-origin`，而代码已经在 SVG transform 中完整指定眼睛的缩放枢轴。这两个原点叠加，使闭眼压缩伴随错误的大幅位移。修复统一采用原点为零的 SVG 坐标变换，并移除竞争的 CSS 眨眼动画，保留正常眨眼。

回归不是只检查 transform 文本存在，而是按连续时间采样，把渲染后的眼睛坐标转回父节点局部空间，检查开眼与闭眼时锚点不离开原位置。覆盖希尔达、大卫、芙丽达、妈妈、阿尔弗、枝枝、小巨魔、巨魔妈妈和沃夫，以及暂停和减少动态模式。

## 手臂、手掌与默认姿态

人形两侧肩膀与放松手部目标使用对称坐标；两侧肘部使用相反的逆运动学弯曲分支，手掌也真正镜像，而不是复制同一只手。默认掌心高度降低，双臂自然下垂，只保留轻微屈肘。上臂和前臂长度保持不变，接触物品仍使用实际世界坐标。

待机降低肩部晃动和呼吸幅度，手势放慢并留下停顿，不再持续挥动。希尔达在没有行走或机关动作时也可以轻微照看挎包；工作动作优先，不用待机覆盖正在进行的接触。四肢仍是风格化二维关节，不是完整手指骨骼或动作捕捉。

## 全体命名角色

阿尔弗增加独立头部、眼睛、嘴形和查看笔记的表现；两位巨魔分别采用较慢的眨眼、呼吸与视线节奏；沃夫增加眼睛、嘴形及轻微浮动。它们与人类共用暂停和减少动态约束，但各自采用适合造型的局部枢轴。对白头像使用正确的物种：巨魔妈妈不再使用小巨魔身份，沃夫不再回退为人类。

枝枝保留 V3.6 的四足落地与独立跟随，并统一眼睛变换规则。这一轮是九个主要命名角色的表情和待机覆盖，不是宣称全部物种都拥有同样数量的肢体动作或自主 AI；装饰性鸟、昆虫与远景元素也不冒充完整 NPC。

## 移除默认文字引导

十二幕场景不再绘制地点说明、操作指令和文字标牌，原有章节卡、场景名称栏及动作指令覆盖层不再默认显示。配重数字、刻度、几何标记和谜题图案保留，场景不是一张空白攻略图。只用于指引的牌子移除；可调查的小纸片等实体仍保留材质轮廓，内容在主动调查时读取。

玩家与人物、物件或机关互动后，反馈采用已有对白或明确标注的「希尔达 · 心想」。系统层的存档失败、导入导出和音频错误仍作为系统消息，不伪装成角色台词。主动打开的手记、菜单和帮助保留可读文字，不做常驻任务清单。

## 道具遮挡与点击优先级

森林大卫的等候位置避开地面绳圈，绳圈与 NPC 的热点同步调整。可拿取物件和若干关键控制件使用独立可见层，移动原始 SVG 节点而不是复制图片，保留原本的局部动画和父级位置。输入命中与热点排列采用一致的优先级：重叠时先拿取小物，再操作机关，再选择人物，避免点击绳子却触发 NPC 对话。

覆盖的物件包括来信、提灯、曲柄、绳圈、铁钩、救援绳、齿轮、羊毛毡以及绞盘、制动和检修轮等关键控制件。完整通关检查发现屋顶锚点会截获已获救大卫的点击，因此同步分开他的安全站位、演出落点和热点，并加入锚点与 NPC 都能真实点击的回归。这不是一个通用三维遮挡引擎；复杂场景仍需逐处实际画面与操作验收。

## 验收

```sh
npm run check
export CHROMIUM_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
.venv/bin/python tests/playthrough.py
.venv/bin/python tests/presentation.py
.venv/bin/python tests/body-motion.py
.venv/bin/python tests/life.py
.venv/bin/python tests/acting.py
.venv/bin/python tests/cast-studio.py
.venv/bin/python tests/art-audio.py
.venv/bin/python tests/native-storage.py
```

`tests/presentation.test.cjs` 检查放松肘部角度、左右手、全部物种、命中优先级与数字谜题保留。`tests/presentation.py` 检查九角色连续眨眼、十二幕文字和 SVG ID、真实鼠标与触控模拟拿绳。独立画廊和章节样本是专项回归，不称为额外完整通关。

完整通关与多数专项使用显式内存 Storage 适配器；原生 HTTP/file 持久化和 NAS HTTPS 检查独立运行。`previews/v3.7/` 保存专项报告和截图。所有受检 HTML 报告必须匹配当前构建的 SHA-256，旧版本文件名不能作为本轮通过依据。自动化不是美术主观验收、真实手机、Safari、Firefox 或低端性能认证。

## 发布

沿用 `bash deploy.sh` 的校验、备份及单文件原子替换流程，新增 presentation 报告为发布条件。NAS 公开响应必须与被测构建逐字节一致，随后运行 `tests/nas-smoke.py` 验证公开页面、眼睛位置、安静界面、拿取及原生 HTTPS 刷新存档。

V3 存档协议不变，不需要清除已有进度。提交本地 main、发布 NAS 和推送 GitHub 是不同动作；这轮不要求创建分支或推送 GitHub。
